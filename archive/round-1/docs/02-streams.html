365 天全栈成长 · Day 2

Buffer 和 Stream
搬家公司的故事

假设你今年 10 岁,刚学编程。今天我们不讲大道理,只讲搬家、接水、汉堡店。

00先讲个麻烦事 — 你正在进入「为什么」

电脑要搬一座「书山」

想象一下:学校图书馆要搬家,有 20 万本书 要搬到新馆。

生活例子

🏠 方法一:全塞进一个大卡车 —— 把所有书一次性装进一辆巨型卡车。问题来了:卡车要多大?可能根本没那么大的车,装到一半车就爆了。

🚲 方法二:每次搬一小箱 —— 用普通小推车,每次搬 20 本,搬很多趟。车不用大,多跑几趟就行,书再多也不怕。

电脑读文件一模一样。一个 2GB 的日志文件(相当于 20 万本书):

  • fs.readFile = 方法一,一次性全读进内存 → 内存可能直接「爆掉」;
  • Stream(流) = 方法二,一次只读一小块(64KB,一小箱),内存永远只用一点点,20GB 的文件也搬得动。
💡 今天所有知识都围绕这一件事:怎么用小小的内存,搬大大的数据,还不把自己累死。
01Buffer:装字节的小箱子 — 你正在进入「字节的世界」

Buffer 是什么?

Buffer(缓冲区)就是一排编了号的小格子,每个格子只能放一个 0~255 的数字。

生活例子

🥚 鸡蛋盒:一个鸡蛋盒有固定数量的格子,每个格子放一个鸡蛋,不多也不少。Buffer 就是「鸡蛋盒」,只不过格子里放的是「字节」。

格子数量在买盒子那一刻就定死了 —— Buffer 创建后长度不能变,想装更多?只能换个新盒子。

字节 ≠ 字!这是今天最重要的坑

生活例子

🍬 把「汉字」想成大糖果,「字节」想成小糖纸。包一颗「中」字大糖果,要用 3 张小糖纸(UTF-8 编码下 1 个汉字 = 3 个字节)。

所以:你说「我有 2 颗糖」,糖纸却有 6 张 —— 数的单位不一样!

'中文'.length              // 2   ← 2 个汉字(糖果)
Buffer.from('中文').length  // 6   ← 6 个字节(糖纸)!
⚠️ 真实世界 bug:如果按字节数把字符串「咔嚓」剪断,可能把一个汉字剪成两半,屏幕上就出现乱码 。这就是糖果被撕开了。

三种做盒子的方法

方法像什么说明
Buffer.alloc(8)买新盒子,格子擦得干干净净安全,最常用
Buffer.allocUnsafe(8)捡别人用过的盒子,可能有剩饭快,但脏,除非你马上全部擦掉重写
Buffer.from('你好')按纸条内容现做一个正好的盒子日常最常用
02Stream:自来水,不是大水缸 — 你正在进入「流动的数据」

Stream 是什么?

Stream(流)就是:数据不一次给你,像自来水一样,一股一股地流过来。

生活例子

🚰 你渴了想喝水,有两种办法:

① 大水缸法:把整条河的水全抽进一个超级大缸,你再喝。你家根本放不下这个缸!(= readFile,内存爆炸)

② 水龙头法:接一根水管,打开水龙头,喝一杯接一杯。你家的杯子很小,但整条河的水你都能喝到。(= Stream)

流过来的每一「股」水,叫做一个 chunk(数据块),默认大约 64KB —— 正好是一盒 Buffer 鸡蛋盒。

import fs from 'node:fs';

// 打开「水龙头」
const tap = fs.createReadStream('很大的日志.txt');

tap.on('data', (chunk) => {
  // 每流来一小块,就接一杯
  console.log('收到一块:', chunk.length, '字节');
});
🎬 其实你在视频网站看视频,用的就是 Stream 思想:电影 2GB,你不会等它全下载完才看,而是看一段缓冲一段。如果全下载完才能看,你可能要等半小时!

Stream 的隐藏超能力:边搬边干活

生活例子

🍟 麦当劳做薯条,不会等所有土豆都削完皮才开始切 —— 削好一个,就传给切的人,切好一个就传给炸的人。三个人同时干活,总时间 ≈ 最慢那个人花的时间,而不是三个人时间加起来。Stream 就是这样:文件还没读完,读到的部分已经在被处理、被写出去了。

03Stream 家族四兄弟 — 你正在进入「认识角色」

四种流,四种角色

流生活里的它干什么例子
Readable
可读流		🚰 水龙头只会往外出水(出数据)读文件、别人发给你的请求
Writable
可写流		🕳️ 下水口只会往里吞水(收数据)写文件、回复给别人的响应
Duplex
双工流		📞 电话既能说又能听,两边互不干扰TCP 网络连接
Transform
转换流		🍊 榨汁机上面扔进橘子,下面流出橙汁压缩、加密、改格式
生活例子

🍊 水果加工厂:橘子从水龙头(果园)流进来 → 第一台榨汁机削皮 → 第二台榨汁 → 下水口装瓶出厂。每个工人只管自己那一道工序,这就是流的「管道」思想。

04Backpressure:汉堡店喊「暂停!」 — 你正在进入「今天最难也最酷的概念」

背压(backpressure)是什么?

当「送水的」比「喝水的」快太多,喝水的人会喊:「等等!先别送了!」 这个「喊停」的动作,就叫背压。

生活例子

🍔 汉堡店出餐窗口:后厨 10 秒做一个汉堡,但前台收银员 1 分钟才能打包卖出去一个。

如果后厨不停手,窗口的汉堡会越堆越高,最后塌下来掉一地(= 内存里数据越堆越多,程序崩溃)。

聪明的做法:前台举个小牌子「窗口满了,后厨停一下」,等卖出去了再喊「继续!」。后厨完全不用换,只要听得懂「停」和「继续」就行。

在代码里,这两个「喊话」是真实存在的:

  • write() 返回 false = 下水口说:「我满了,别写了!」
  • 'drain' 事件 = 下水口说:「我排空了,继续!」(drain 就是「排干」的意思)
const ok = out.write(chunk);
if (!ok) {
  // 窗口满了!后厨(可读流)先停下
  src.pause();
  out.once('drain', () => {
    // 窗口空了,后厨继续!
    src.resume();
  });
}

👇 动手玩一玩:你来当后厨

点「做一个汉堡」= 后厨生产;「卖掉一个」= 前台销售。窗口最多放 5 个。试试狂点生产,看会发生什么!

🏆 记住了:背压不是错误,不是 bug,它是健康的自我保护。就像吃饭细嚼慢咽 —— 问题不是「吃得太慢」,而是「塞得太快还不停」。
05pipeline:请一个流水线管家 — 你正在进入「实战武器」

pipeline:自动管好整条流水线

手写 pause/resume 太累了。Node.js 给了我们一个「管家」:pipeline,它自动处理背压、自动收拾残局。

生活例子

🎢 你自己去接水管,要自己拧阀门、自己盯水位,万一中间管子爆了,水漫金山(内存泄漏)。

pipeline 像游乐园的自动传送带管理员:水流快慢它自动调节;任何一节出问题,它立刻关停整条线,并把剩下的水清理干净,绝不淹了你的房子。

import { pipeline } from 'node:stream/promises';
import fs from 'node:fs';
import zlib from 'node:zlib';

// 读文件 → 榨汁机(压缩)→ 写文件,一句话搞定
await pipeline(
  fs.createReadStream('大日志.txt'),   // 🚰 水龙头
  zlib.createGzip(),                    // 🍊 榨汁机:压成果汁
  fs.createWriteStream('大日志.txt.gz') // 🕳️ 下水口
);

这三行代码背后,pipeline 管家帮你做了四件事:

  • ✅ 自动处理背压(快了喊停,空了喊继续)
  • ✅ 任何一个环节出错,关闭所有流,不浪费内存
  • ✅ 出错时把错误告诉你(await 会抛异常)
  • ✅ 全部完成后正常返回

🧠 小测验:你真的懂了吗?

1.「你好」这两个汉字,Buffer.from('你好').length 是几?
6。一个汉字 UTF-8 编码占 3 个字节(一颗大糖果用 3 张糖纸),2 × 3 = 6。
2. 读一个 10GB 的文件,用 readFile 会怎么样?
它想一次性把 10GB 全塞进内存 —— 相当于想一口吞掉整条河,内存大概率直接爆掉(程序崩溃)。应该用 Stream,一杯一杯地喝。
3. write() 返回 false,你应该继续写还是停下来?
停下来!这相当于前台举牌「窗口满了」。正确做法是等 'drain'(排空了)事件再继续写 —— 这就是处理背压。
4. Transform 流像生活中的什么?
榨汁机:上面扔进橘子(写入数据),下面流出橙汁(读出变换后的数据)。压缩、加密都是它。
字节小,汉字大,糖纸三张包一颗。 数据大,别硬吞,水龙头下一杯杯。 窗口满,喊暂停,drain 一响再继续。 流水线,找管家,pipeline 全搞定。
