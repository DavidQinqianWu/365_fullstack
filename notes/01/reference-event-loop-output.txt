你现在看到的结果其实非常有价值，我们拆开看就清楚了。

# 2. 为什么 `[17]` 跑到最前面？

你可能最困惑这个：

```text
[17] synchronous code finished
```

为什么不是最后？

因为你这里：

```ts
setTimeout(...);
setImmediate(...);

while (Date.now() < spinUntil) {
}

log("[17] synchronous code finished");
```

这个 `while` 是**同步阻塞**。

Node 在执行整个 top-level module 的时候：

```text
开始执行 module
      ↓
注册 timer
      ↓
注册 immediate
      ↓
while 阻塞 1 秒
      ↓
[17]
      ↓
整个 module 执行结束
      ↓
Event Loop 才开始处理异步任务
```

所以：

```text
[17]
```

一定属于**同步代码**。

因此它当然在：

```text
Promise
nextTick
setTimeout
setImmediate
```

之前。

# 3. 为什么 `[5] Promise` 在 `[4] nextTick` 前面？

这是你这个实验最有意思的地方。

你使用的是：

```text
order.ts
```

而且从代码看：

```ts
import { readFile } from "node:fs";
```

以及：

```ts
import.meta.filename
```

说明你是在 **ESM** 环境下运行。

你注册：

```js
process.nextTick(() => {
  console.log('[4]');
});

Promise.resolve().then(() => {
  console.log('[5]');
});

queueMicrotask(() => {
  console.log('[6]');
});

process.nextTick(() => {
  console.log('[7]');
});
```

最终：

```text
[5] Promise
[6] queueMicrotask
[4] nextTick
[7] nextTick
```

### 为什么？

因为这是 **ESM 顶层执行的特殊情况**。

可以粗略理解成：

```text
ESM module evaluation
        ↓
当前同步代码
        ↓
microtask queue
        ↓
nextTick
```

所以：

```text
Promise
queueMicrotask
nextTick
nextTick
```

---

# 4. 但是这里有一个非常重要的地方

你千万不要因此得出：

> “Promise microtask 永远比 nextTick 优先。”

❌ 不对。

更准确的是：

### CommonJS

```text
同步代码
   ↓
nextTick
   ↓
microtask
```

### ESM 顶层

```text
同步代码
   ↓
microtask
   ↓
nextTick
```

所以你这个实验其实同时证明了：

> **模块类型会影响你观察到的 nextTick / microtask 顺序。**

# 5. `[8]` 为什么在 `[9]` 前面？

你看到：

```text
[8] setTimeout(0)
[15] controlled setTimeout(0)

[9] setImmediate()
[16] controlled setImmediate()
```

这次是：

```text

```

这完全合理。

# 6. `[15]` 为什么也跑在 `[9]` 前？

这是因为你注册的顺序：

```text
Experiment 2:

setTimeout
setImmediate

Experiment 4:

setTimeout
setImmediate
```

Event Loop 进入 timers 的时候：

```text
timers
 │
 ├── [8]
 │
 └── [15]
```

所以：

```text
[8]
[15]
```

然后到了 check：

```text
check
 │
 ├── [9]
 └── [16]
```

所以：

```text
[9]
[16]
```

# 8. 但是你这个实验有一个设计问题

这也是为什么你感觉：

> “这个输出怎么看的很奇怪。”

因为你现在实际上把：

```text
Experiment 1
Experiment 2
Experiment 3
Experiment 4
```

**全部放在同一个 Event Loop 中了。**

所以它们并不是：

```text
Experiment 1
    ↓
结束

Experiment 2
    ↓
结束

Experiment 3
```

而实际上是：

```text
            同一个 Event Loop
                  │
      ┌───────────┼────────────┐
      │           │            │
   Exp 1        Exp 2        Exp 3
      │           │            │
      └───────────┼────────────┘
                  │
               Exp 4
```

所有：

```js
setTimeout()
setImmediate()
Promise.then()
process.nextTick()
readFile()
```

都在**同一个 Node.js 进程里注册了**。

所以它们当然会互相影响。

# 10. 如果你现在只想理解 Event Loop，我建议你先跑这个最小版本

### `03-io-callback.ts`

```ts
import { readFile } from "node:fs";

console.log("[1] main module");

readFile(import.meta.filename, () => {
  console.log("[2] I/O callback → poll");

  process.nextTick(() => {
    console.log("[3] nextTick");
  });

  Promise.resolve().then(() => {
    console.log("[4] Promise microtask");
  });

  setImmediate(() => {
    console.log("[5] setImmediate → check");
  });

  setTimeout(() => {
    console.log("[6] setTimeout → timers");
  }, 0);

  console.log("[7] I/O callback synchronous end");
});
```

你会得到类似：

```text
[1] main module

[2] I/O callback → poll
[7] I/O callback synchronous end
[3] nextTick
[4] Promise microtask
[5] setImmediate → check
[6] setTimeout → timers
```

这个实验非常值得你自己画一遍：

```text
              Event Loop
                   │
                 poll
                   │
                   ▼
            I/O callback
                   │
             ┌─────┴─────┐
             │           │
           sync       注册异步任务
             │           │
             ▼           │
            [7]          │
                         │
                         ▼
                    nextTick
                         │
                         ▼
                    microtask
                         │
                         ▼
                       check
                         │
                         ▼
                  setImmediate
                         │
                         ▼
                    next timers
                         │
                         ▼
                    setTimeout
```

### 🎯 所以你刚才这个输出其实没有“乱”

真正的问题是：**你把 4 个实验同时塞进了同一个 Event Loop，所以结果不再是“每个实验独立的答案”，而是 4 个实验的 callback 被 Node 按实际调度规则混合执行。**

如果你是在**系统学习 Node.js Event Loop**，我强烈建议把实验拆成独立文件。这样你每次只观察一个问题，会清晰很多。
