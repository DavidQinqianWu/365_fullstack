## Review 清单(逐条打勾,每条写一句「查了什么、结论是什么」)

- [ ] 每一个索引都能指出它服务哪条查询吗?反过来,负载里的每条热点查询都能指出它用哪个索引吗?(Day 34)
- [ ] 有没有前缀重复的索引(一个索引的键列正好是另一个的前缀)?(Day 32)
- [ ] 每一个外键列都有以它打头的索引吗?(Day 32)
- [ ] 写得最多的那几列(PATCH 改什么、PUT 改什么)被哪些索引覆盖了?这些更新还能 HOT 吗?(Day 32)
- [ ] `SET STATISTICS 1000` 解决了什么,又让哪种查询变差了?这个代价被记录下来了吗?(Day 30 / 34)
- [ ] 有没有接口会一次读出整张表?数据量再大十倍时会怎样?(Day 19 / 34)
- [ ] `?q=` 的最坏情况是什么样的关键词?它现在要多久?有没有办法知道生产上这种请求占多少?(Day 33 / 34)
- [ ] 这些索引是怎么建出来的(`schema.sql` 整个重建)?在一张有数据、正在被读写的生产表上,同样的 `CREATE INDEX` 会发生什么?(Day 34 / Week 9)
