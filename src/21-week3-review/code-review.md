# Week 3 API review(nest-lab)

> 用 `nest-lab/docs/api-design.md` 当检查清单,review `nest-lab/` 的 tasks / users 接口。
> 这次 review 的对象是**对外契约**:看 `openapi.json`、`/docs` 页面、用 curl 发真实请求,必要时再看源码。
> 目标:至少找出 2 个问题。一个都没找到 = review 得不够仔细。
> 复盘日不改功能:问题先记下来,改法写清楚,真正动手放到对应的那一周。

## Review 清单(逐条打勾,每条写一句「查了什么、结论是什么」)

- [ ] 每个写接口都声明并真的返回 422 + `application/problem+json`;所有 4xx 都是 problem+json(api-design §4–5,Day 16 / 17 / 20)
- [ ] 没有任何接口直接返回内部对象 / 仓储里的实体,所有成功响应都走映射函数(§6,Day 18)
- [ ] **每一个**集合接口都有分页、`limit` 默认值和上限(§7,Day 19)
- [ ] 每一个资源都在版本化方案里;破坏性变更走新版本;不带版本号的路径有没有隐患(§8,Day 19)
- [ ] `openapi.json` 与代码一致;**文档声明的状态码与真实行为一致**(§9,Day 20)
- [ ] 201 的 `Location` 指向的地址真的能用、和版本化方案一致(§2,Day 15 / 19)
- [ ] 弃用信息(`Deprecation` / `Sunset` / `Link`)在该出现的响应上都出现了(§8,Day 19)
- [ ] 没有把可伪造的请求头当成可信身份;错误和日志里没有带出不该带出的东西(§5,Day 11 / 13 / 17)
