# 覆盖索引（Covering Index）：为什么这个查询不用回表

> 2026-10-04 · 数据库 · 约 13 分钟 · 来源：每日全栈15min 自动生成

## 摘要

普通索引找到行之后还要回主键索引取整行数据，叫回表。如果索引本身就包含了查询所需的全部字段，数据库可以直接从索引返回结果（Index Only Scan），少一次随机 I/O。这是理解「索引为什么快」之后最实用的进阶半步，改一条索引就能让慢查询起飞。

## 要点

- 二级索引的叶子存的是主键值，取其他字段必须再查一次聚簇索引，即回表
- 把查询里 SELECT 和 WHERE 用到的字段一起建进索引，就构成覆盖索引
- EXPLAIN 里出现 Index Only Scan / Using index 说明成功命中覆盖
- 代价是索引更大、写入要维护更多列，只为高频查询量身定制
- 遵守最左前缀原则：WHERE 条件要从复合索引的最左列开始匹配

## 示例

MySQL 中创建覆盖索引并验证查询是否免回表：

```sql
-- 订单表：为「查某用户的订单金额」这个高频查询建复合索引
CREATE INDEX idx_orders_user_amount
  ON orders (user_id, amount);

-- 查询只用了索引内的两列 → Index Only Scan，不回表
EXPLAIN
SELECT amount FROM orders WHERE user_id = 42;
-- Extra 列显示: Using index  ✅ 覆盖成功

-- 反例：select 了索引外的列，就要回表取整行
EXPLAIN
SELECT amount, status FROM orders WHERE user_id = 42;
-- Extra 列看不到 Using index  ❌ 发生回表
```

## 踩坑提醒

滥用覆盖索引：给表里一半的列都建索引，会让写入变慢、缓冲池被索引占满，整体性能反而下降。只覆盖被频繁执行、且性能敏感的查询。
