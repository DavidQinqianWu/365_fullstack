# SQL 查询三板斧：SELECT、WHERE 与排序分页

> 2026-10-09 · 数据库 · 约 12 分钟 · 来源：每日全栈15min 自动生成

## 摘要

数据库是请求的终点站。本文讲清最常用也最该用好的 SQL 查询模式：SELECT 选列、WHERE 过滤、ORDER BY 排序、LIMIT/OFFSET 分页，以及为什么查询条件要尽量命中索引列。写对一条查询，往往比装一个缓存更有效。

## 要点

- SELECT 只取需要的列，避免 SELECT * 拖慢查询与传输
- WHERE 过滤应在数据库完成，不要把全表拉回应用层再筛
- ORDER BY 必须指定，否则结果顺序不保证稳定
- LIMIT + OFFSET 实现分页，OFFSET 大时性能会退化
- WHERE 条件列上应有索引，否则全表扫描成本随数据线性增长

## 示例

一个带过滤、排序、分页的实用查询，及常用索引的创建方式。

```sql
-- 查询最近注册的活跃用户（第 2 页，每页 20 条）
SELECT id, name, email, created_at
FROM users
WHERE status = 'active'
  AND created_at >= '2026-01-01'
ORDER BY created_at DESC
LIMIT 20 OFFSET 20;  -- OFFSET = (页码-1) * 每页条数

-- 为常用过滤条件建索引，让上面的 WHERE 走索引而非全表扫描
CREATE INDEX idx_users_status_created
  ON users (status, created_at DESC);
```

## 踩坑提醒

分页时忘记 ORDER BY，OFFSET 翻页会出现重复或漏掉的数据——因为未排序的结果顺序是未定义的，同一句话执行两次可能返回不同顺序。
