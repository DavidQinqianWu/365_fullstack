# HTTP 请求的一生：路由、中间件与 JSON 响应

> 2026-10-09 · 后端 · 约 13 分钟 · 来源：每日全栈15min 自动生成

## 摘要

后端的核心工作是接住前端的请求并给出结构化响应。本文以 Express 为例讲解请求如何流经中间件、如何按路径与方法匹配路由、以及如何返回规范的 JSON 响应和状态码。这是把浏览器请求转成业务逻辑的入口知识。

## 要点

- 后端本质是一个「监听端口、按 method+path 分发」的循环
- 中间件按注册顺序执行，必须在响应前调用 next() 才能继续
- 路由处理函数的 (req, res) 分别代表请求与响应两个对象
- 用合适的 HTTP 状态码表达结果：200/201/400/404/500
- res.json() 会自动设置 Content-Type: application/json

## 示例

Express 中最小可用的 JSON API：日志中间件 + GET/POST 路由 + 错误处理。

```javascript
const express = require('express');
const app = express();

app.use(express.json()); // 解析 JSON body，挂在所有路由之前

// 中间件：每个请求都会经过这里
app.use((req, res, next) => {
  console.log(`${req.method} ${req.path}`);
  next(); // 不调用 next() 请求就停在这里
});

const users = [{ id: 1, name: 'Ada' }];

app.get('/api/users', (req, res) => {
  res.json(users); // 自动带 Content-Type: application/json
});

app.post('/api/users', (req, res) => {
  const { name } = req.body;
  if (!name) return res.status(400).json({ error: 'name 必填' });
  const user = { id: Date.now(), name };
  users.push(user);
  res.status(201).json(user); // 创建成功用 201
});

app.listen(3000);
```

## 踩坑提醒

新手常忘记 app.use(express.json())，导致 req.body 是 undefined，然后怀疑前端没发数据。这个解析中间件必须放在所有读取 body 的路由之前注册。
