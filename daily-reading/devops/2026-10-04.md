# Docker 镜像分层与构建缓存：让镜像构建快一个数量级

> 2026-10-04 · DevOps · 约 12 分钟 · 来源：每日全栈15min 自动生成

## 摘要

Dockerfile 每条指令产生一个只读层，层有变化时它之后的所有层缓存全部失效。把变动频繁的步骤（拷贝代码、安装依赖）放到后面、变动少的（基础镜像、系统依赖）放前面，构建就能稳定命中缓存，从每次几分钟降到几秒。这是用好 Docker 的第一个杠杆。

## 要点

- 每条 RUN/COPY/ADD 指令生成一个层，层内容不变就可复用缓存
- 某层失效后，它后面的所有层都必须重建，顺序决定缓存命中率
- 先 COPY 依赖清单（package.json、requirements.txt）再 COPY 源码，依赖不变就不重装
- 用 .dockerignore 排除 node_modules、日志等，避免污染缓存上下文
- 用 docker build 输出里的 CACHED 标记确认哪几层命中了缓存

## 示例

优化顺序后的 Node.js Dockerfile，依赖不变时构建秒级完成：

```dockerfile
FROM node:20-slim
WORKDIR /app

# 1) 先拷依赖清单——只要不换依赖，下面这层就一直命中缓存
COPY package.json package-lock.json ./
RUN npm ci --omit=dev

# 2) 再拷频繁变动的源码，改动只重建这一层
COPY src ./src

# 3) 以非 root 用户运行，收尾层放前面已有的 ENV 声明之后
USER node
ENV NODE_ENV=production
EXPOSE 3000
CMD ["node", "src/server.js"]
```

## 踩坑提醒

把 COPY . . 写在安装依赖之前：任何源码改动都会让缓存失效，依赖重装一遍，构建时间暴涨。先把锁文件拷进去装依赖，再拷源码，是新手最该养成的一条顺序习惯。
