# HTTP 缓存：Cache-Control 与 ETag 如何省掉重复请求

> 2026-10-04 · 前端 · 约 12 分钟 · 来源：每日全栈15min 自动生成

## 摘要

浏览器不是每次都重新下载资源。Cache-Control 让强缓存直接命中本地副本，ETag 让协商缓存用一次轻量往返确认资源是否变了。搞清这两层机制，你写的每个 Web 应用都能少传大量重复字节，首屏更快、服务器压力更小，是前端性能优化的第一块基石。

## 要点

- 强缓存：Cache-Control: max-age=N 内浏览器不发请求，直接读本地副本
- 协商缓存：过期后带 If-None-Match 问服务器，没变就返回 304 且 body 为空
- ETag 是资源的指纹，内容变了指纹才变，比 Last-Modified 更精确
- HTML 入口文件用 no-cache，静态资源带 hash 的文件名用 max-age=31536000, immutable
- 304 的响应只有响应头，几十字节换几百 KB，代价极小

## 示例

服务端为静态资源与 API 分别设置两级缓存策略的响应头示例：

```html
# 构建产物带内容 hash，可以放心强缓存一年
/assets/app.a1b2c3.js:
  Cache-Control: public, max-age=31536000, immutable

# index.html 每次都要确认，避免发版后用户拿到旧入口
/index.html:
  Cache-Control: no-cache   # 缓存，但每次必须向服务器验证(ETag)

# API 响应：短缓存 + 协商缓存
/api/articles:
  Cache-Control: public, max-age=60
  ETag: "v42"

# 浏览器第二次请求时自动带上：
# If-None-Match: "v42"  →  没变则服务器返回 304 Not Modified
```

## 踩坑提醒

最常见误区是给 index.html 也设 max-age=31536000：发版后老用户仍命中旧入口，引用的还是旧 hash 资源，页面直接白屏或报错。入口文件永远用 no-cache。
