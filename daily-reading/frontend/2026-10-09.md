# 用 fetch 与 async/await 优雅地发起 HTTP 请求

> 2026-10-09 · 前端 · 约 12 分钟 · 来源：每日全栈15min 自动生成

## 摘要

前端一切数据都来自请求。本文讲解如何用 fetch 发起 GET/POST 请求、用 async/await 组织异步流程，以及响应的 status 与 JSON 解析关系。掌握它，你就能把一个请求从浏览器干净地送到后端，并正确处理成功与失败两种结局。

## 要点

- fetch 返回的是 Promise，网络失败会 reject，但 HTTP 4xx/5xx 不会
- 必须检查 response.ok 再决定解析 response.json()
- async/await 让异步代码保持同步的书写顺序，便于阅读和维护
- POST 请求要设置 method、headers 的 Content-Type 与 JSON.stringify 的 body
- finally 适合放 loading 状态的收尾逻辑

## 示例

用 fetch 请求用户列表，处理成功、HTTP 错误与网络错误三种结局。

```javascript
async function getUsers() {
  const res = await fetch('/api/users');
  if (!res.ok) {
    // HTTP 404 / 500 都走这里：不抛错，只会 ok = false
    throw new Error(`HTTP ${res.status}: ${await res.text()}`);
  }
  return res.json(); // 注意：json() 也是异步的
}

async function createUser(name) {
  const res = await fetch('/api/users', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ name }),
  });
  if (!res.ok) throw new Error(`创建失败: ${res.status}`);
  return res.json();
}
```

## 踩坑提醒

最常见的坑是以为 fetch 会自动对 404/500 抛异常——它不会，只有断网才 reject。忘记检查 res.ok 会把后端返回的错误页当正常数据解析。
