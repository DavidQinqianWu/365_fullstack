# ELI5 课程生成规范

目标读者:有 7 年前端经验、但后端是新手的学员。**讲解深度不打折,讲法要像讲给 10 岁小孩听。**
ELI5 的意思是「入口要低」,不是「内容要浅」——每个概念最终都要落到真实术语、真实代码、能复现的实验上。

## 1. 每个新概念都走「五步台阶」

| 步 | 做什么 | 示例(以 backpressure 为例) |
|---|---|---|
| ① 一句话大白话 | 不用任何术语,一句话说清它解决什么麻烦 | 「下游吃不下时,让上游先别塞。」 |
| ② 生活类比 | 一个具体场景,最好沿用全课程的主线比喻(餐厅/服务员/分店/传送带) | 传送带末端的人吃不过来,就按红灯让传送带停。 |
| ③ 类比的边界 ⚠️ | **必写**:这个比喻在哪里会骗人,真实系统哪里不一样 | 真实的「红灯」只是 `write()` 返回 false,上游不理它也能继续写——内存会爆,不会被物理拦住。 |
| ④ 真实术语 | 此时才给出英文术语 + 一句精确定义 | backpressure、highWaterMark、`drain` 事件 |
| ⑤ 动手验证 | 一个最小实验:**先让学员预测结果,再运行** | 「猜一猜:不处理 drain,写 1GB 内存会涨到多少?」 |

第 ③ 步最容易漏,也最重要:没有边界的类比会在面试追问时变成错误理解。

## 2. 类比规则

- **一条主线比喻贯穿多天**(目前是「餐厅」:服务员=线程/event loop,分店=进程,传送带=Stream)。新概念优先挂到已有角色上,不要每天换一套世界观。
- 一个概念只配**一个**主类比,最多再加一个补充类比;比喻堆太多等于没比喻。
- 类比必须能映射到具体机制:比喻里的每个角色都要能指出它对应的真实组件(写成一张「比喻 ↔ 真实」对照小表)。
- 概念先行,语言为器:类比讲的是通用概念,讲完再说「在 Node 里叫什么 / .NET、Java、Go 里叫什么」。

## 2.5 教学模板:后端 = NestJS,数据库 = PostgreSQL

- **后端知识点从 NestJS 切入**,每个主题走「三步走」:
  1. **在 Nest 里写出来、跑起来**:先给能运行的 Nest 代码(Controller / Provider / Guard / Interceptor / Pipe……),学员先看到效果;
  2. **掀开盖子**:讲这个机制的通用原理(Nest 替你做了什么、不用框架时要自己做什么),五步台阶主要用在这一步;
  3. **跨语言对照**:ASP.NET Core / Spring Boot / Go 里叫什么。
- **数据库知识点在 PostgreSQL 上讲**:实验先在 psql 里做(docker 起实例),再接回 Nest 项目(原生 SQL 用 `pg`,ORM 用 Prisma);最后补一句 SQL Server / MySQL 的差异。
- **从 Week 2 起,后端习题写进同一个持续生长的 `nest-lab/` 项目**,讲义里写清「今天在 nest-lab 里新增/修改了哪些文件」;不要每天另起一次性脚本。
- **例外**:Week 1 的运行时机制用裸 Node 讲(Nest 就跑在它上面),但每节课结尾加一段「🧩 这在 NestJS 里对应什么」。
- Nest 的 API 是**入口,不是重点**:不要罗列装饰器参数,讲到能写、能解释原理即可。

## 3. 每日 HTML 文档结构(沿用现有 Day 1–4 风格)

1. 📖 目录
2. 接上回:用一句话把昨天的比喻接过来,引出今天的「新麻烦」
3. 📇 概念卡(每张都按五步台阶写,含「比喻 ↔ 真实」对照表和 ⚠️ 类比边界)
4. 🌍 跨语言对照(Node / C#/.NET / Java / Go),并提醒更新 roadmap 顶部对照表
5. 🛠️ 今日习题(先预测再运行;至少一题是「解释给别人听」类)
6. ✅ 总结与自测:3–5 个**主动回忆**问题(合上文档能答),不是复述题

时长按 roadmap 规定:每天 1.5 小时(约 50 min 学习 + 30 min 习题 + 10 min 整理)。

## 4. 学习方法(来自 learn 技能的原则,落到课程里)

- **先诊断再教**:新一天开始前,先看 `progress.md` 和上一天 `notes.md` 的订正区,上一天有没吃透的点就在「接上回」里补一句。
- **预测先于运行**:每个实验都先写「你猜会输出什么?」,再给运行命令。
- **主动回忆 > 重读**:默写骨架(notes.md)只放问题和空白,不放答案。
- **不灌满**:一天最多 2–3 张新概念卡;超出就拆到下一天,不硬塞。
- 讲错要认:批改时直接指出错在哪、为什么错,不空夸。
