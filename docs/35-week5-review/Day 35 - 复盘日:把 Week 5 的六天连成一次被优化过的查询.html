为什么这张图值 25 分钟

前几周的图回答「请求经过哪些站」「数据怎么可靠地写进去」;今天这张图回答「同一条 SQL 为什么有时快、有时慢,快慢由谁决定」。面试里问「这个接口为什么慢」,能从「优化器估了多少行、选了哪个计划、计划里哪个节点扔掉了多少行」讲到「统计信息为什么会估错、怎么修、修了有什么代价」的人,说明他调过真实的慢查询,而不是只背过「加索引」。

这张图在 MySQL 和 SQL Server 里大体一样:解析 → 优化器读统计信息 → 基于成本选计划 → 执行 → 记进统计(Performance Schema / Query Store)。差别在细节:InnoDB 的二级索引存的是主键而不是行位置,SQL Server 会缓存计划并用参数嗅探。你画的是「一个基于成本的优化器怎么工作」,不是「PostgreSQL 的实现细节」。
