为什么这张图值 25 分钟

三周前的图回答「框架怎么组织代码」,上周的图回答「调用方能依赖什么」;今天这张图回答「数据到底是在哪一刻、靠什么保证真的存好了」。面试里问「一个请求写数据库时发生了什么」,能从连接池讲到事务、从约束讲到 SQLSTATE 再讲回 problem+json 的人,说明他知道数据的正确性是由哪几层共同保证的。

这张图在 ASP.NET Core(EF Core / Npgsql)、Spring(HikariCP / JDBC)、Go(pgxpool)里几乎一样:借连接 → 开事务 → 参数化写入 → 约束检查 → 提交 → 归还连接 → 映射成响应。你画的是「后端怎么把一份数据可靠地写进关系数据库」,不是「nest-lab 的实现细节」。
